# בוחן רקורסיה

ענו על כל השאלות, ואז לחצו על **הגשת התשובות** כדי לראות את הציון ואת התיקונים.

## מהי רקורסיה?
- [ ] פונקציה שרצה שוב ושוב בתוך לולאה
  > לולאות חוזרות על קוד, אבל רקורסיה עוסקת בפונקציה שקוראת **לעצמה**, לא בלולאות.
- [x] פונקציה שקוראת לעצמה כדי לפתור גרסה קטנה יותר של אותה בעיה
  > נכון! פונקציה רקורסיבית פותרת חתיכה קטנה ומעבירה את השאר לעותק קטן יותר של אותה בעיה.
- [ ] פונקציה שקוראת לפונקציה אחרת שתעזור לה
  > לקרוא לפונקציה אחרת זה רגיל לגמרי. זה הופך לרקורסיה רק כשהפונקציה קוראת **לעצמה**.
- [ ] משתנה ששומר פונקציה כדי שאפשר יהיה להשתמש בה שוב
  > אפשר לשמור פונקציה במשתנה ב-Python, אבל זה לא קשור בכלל לרקורסיה.
> רקורסיה פירושה שפונקציה קוראת לעצמה. כל קריאה עובדת על גרסה קטנה יותר של הבעיה, עד שהיא מגיעה למקרה פשוט מספיק כדי לענות עליו ישירות.

## למה מתכנתים אוהבים להשתמש ברקורסיה לבעיות כמו מגדלי האנוי?
- [ ] רקורסיה תמיד רצה מהר יותר מלולאה שעושה את אותה עבודה.
  > לא נכון. רקורסיה לרוב איטית יותר, כי כל קריאה מוסיפה עבודה ותופסת מקום במחסנית הקריאות.
- [ ] רקורסיה משתמשת בפחות זיכרון, כי היא לא צריכה משתנים בכלל.
  > זה בדיוק הפוך: כל קריאה פעילה נשארת במחסנית הקריאות, כך שרקורסיה עמוקה יכולה לצרוך יותר זיכרון.
- [x] היא מתארת את הבעיה בעזרת עותק קטן יותר של עצמה.
  > בדיוק. "תזיז `n - 1` דיסקיות, תזיז את הגדולה, תחזיר את `n - 1` הדיסקיות" הופך חידה קשה לכמה שורות קוד קצרות וברורות.
- [ ] ל-Python אין שום דרך אחרת לפתור חידות כמו זו.
  > כל מה שנפתר ברקורסיה אפשר לפתור גם בלולאות. רקורסיה היא בחירה שלרוב הופכת את הקוד לפשוט יותר.
> רקורסיה שימושית כי קל לחשוב איתה: אם אפשר לתאר בעיה בעזרת גרסה קטנה יותר של עצמה, הקוד לרוב כמעט כותב את עצמו.

## אילו מהבעיות האלה מתאימות לרקורסיה?
- [x] חיבור כל המספרים ברשימה שעשויה להכיל רשימות אחרות
  > מתאים: כל רשימה פנימית היא שוב אותה בעיה, רק קטנה יותר.
- [ ] המרה של טמפרטורה אחת מצלזיוס לפרנהייט בעזרת נוסחה אחת
  > זה חישוב אחד. אין כאן גרסה קטנה יותר של הבעיה להעביר הלאה.
- [ ] הדפסת התאריך של היום פעם אחת בראש דוח
  > זה צעד בודד שאי אפשר לפרק לתת-בעיות קטנות ודומות.
- [x] בדיקה אם מילה היא פלינדרום (פלינדרום הוא מילה שנקראת אותו דבר מההתחלה ומהסוף)
  > מתאים: משווים את האות הראשונה והאחרונה, ואז בודקים באותה דרך את המילה הקצרה יותר שבאמצע. מילה עם 0 או 1 אותיות היא מקרה הבסיס.
- [x] ספירת כל האנשים בעץ משפחה, שבו לכל אדם עשויים להיות ילדים
  > מתאים: החלק של כל ילד בעץ הוא עץ משפחה קטן יותר, שנספר באותה דרך.
> בעיה מתאימה לרקורסיה כשאפשר לפרק אותה ל**תת-בעיות קטנות ודומות**, עם מקרה פשוט בתחתית שאפשר לענות עליו ישירות.

## בפונקציה הזו, איזו שורה בודקת את **מקרה הבסיס**?
```python
def countdown(n):
    if n == 0:
        print("Liftoff!")
        return
    print(n)
    countdown(n - 1)
```
- [ ] `print(n)`
  > השורה הזו רק מדפיסה את המספר הנוכחי. היא רצה בכל קריאה חוץ מהאחרונה.
- [ ] `countdown(n - 1)`
  > זה **הצעד הרקורסיבי**: הפונקציה קוראת לעצמה עם מספר קטן יותר.
- [ ] `def countdown(n):`
  > השורה הזו רק מגדירה את הפונקציה. היא לא קובעת מתי הרקורסיה נעצרת.
- [x] `if n == 0:`
  > נכון! כש-`n` שווה 0, הפונקציה עונה ישירות וחוזרת בלי לקרוא לעצמה.
> **מקרה הבסיס** הוא המקום שבו הרקורסיה נעצרת. **הצעד הרקורסיבי** קורא לפונקציה על בעיה קטנה יותר. ביחד הם מוודאים שכל קריאה מתקדמת לכיוון מקרה הבסיס, כך שהפונקציה בסופו של דבר מסתיימת.

## מה הקוד הזה מדפיס?
```python
def mystery(n):
    if n == 0:
        return 0
    return n + mystery(n - 1)

print(mystery(4))
```
- [x] 10
  > נכון! `4 + 3 + 2 + 1 + 0 = 10`.
- [ ] 24
  > זה `4 * 3 * 2 * 1`. הפונקציה **מחברת** את `n`, היא לא כופלת.
- [ ] 0
  > מקרה הבסיס מחזיר 0, אבל ה-0 הזה מתווסף אחר כך למספרים שמחכים בקריאות שמעליו.
- [ ] 4
  > הקריאה הראשונה מחזירה `4 + mystery(3)`, לא רק 4. היא צריכה לחכות לקריאות שמתחתיה.
> כל קריאה מחכה לקריאה שמתחתיה. כש-`mystery(0)` מחזירה 0, התשובות עולות חזרה למעלה: `1 + 0`, אחר כך `2 + 1`, אחר כך `3 + 3`, ואז `4 + 6 = 10`. הפונקציה מחברת את כל המספרים מ-`n` ועד 0.

## מה קורה כשהקוד הזה רץ?
```python
def multiply(a, b):
    if b == 0:
        return 0
    return a + multiply(a, b - 2)

print(multiply(4, 3))
```
- [ ] הוא מדפיס 12, כי 4 מחובר שלוש פעמים
  > זה היה נכון עם `b - 1`. כאן `b` קופץ למטה ב-2 בכל פעם.
- [x] הוא קורס עם `RecursionError`
  > נכון! `b` עובר 3, 1, -1, -3... ומדלג מעל 0, כך שאף פעם לא מגיעים למקרה הבסיס.
- [ ] הוא מדפיס 8, כי 4 מחובר פעמיים לפני ש-`b` נגמר
  > אין שום נקודה שבה `b` נוחת על 0, כך שהפונקציה אף פעם לא מחזירה מספר בכלל.
- [ ] הוא מדפיס 0, כי מקרה הבסיס מחזיר 0
  > מקרה הבסיס מחזיר 0 רק כש-`b == 0`, וזה אף פעם לא קורה כאן.
> לא מספיק שיש מקרה בסיס: כל קריאה חייבת להתקדם **לכיוונו**. אם הצעד הרקורסיבי מדלג מעל מקרה הבסיס, הפונקציה קוראת לעצמה עד ש-Python עוצר אותה.

## אילו טענות על הקריאה `multiply(4, 5000)` נכונות? (`multiply` משתמשת בגרסה הנכונה עם `b - 1`.)
- [ ] היא מדפיסה 20000 בלי שום בעיה.
  > מגבלת הרקורסיה של Python היא כברירת מחדל בערך 1000 רמות, אז היא אף פעם לא מגיעה כל כך רחוק.
- [x] מקרה הבסיס שלה נכון.
  > נכון. `b` יורד ב-1 בכל פעם, אז בסופו של דבר הוא יגיע ל-0.
- [x] בערך 5000 קריאות מחכות במחסנית באותו זמן.
  > נכון. אף קריאה לא יכולה להסתיים עד שהקריאות שמתחתיה מסתיימות, אז כולן נערמות.
- [ ] הוספת עוד RAM למחשב תאפשר לה להסתיים.
  > למחסנית הקריאות יש גודל קטן וקבוע שנקבע על ידי מערכת ההפעלה. עוד RAM לא מגדיל אותה.
- [x] Python עוצר אותה עם `RecursionError`.
  > נכון. Python מגביל רקורסיה לבערך 1000 רמות וזורק את השגיאה הזו כדי להגן על התוכנית.
> גם פונקציה רקורסיבית נכונה יכולה להיכשל אם היא נכנסת עמוק מדי. כשהעומק גדל עם גודל הקלט, לולאת `for` או `while` רגילה היא בדרך כלל הבחירה הטובה יותר.

## מהי **ממואיזציה** (memoization)?
- [ ] לגרום לפונקציה לקרוא לעצמה על גרסה קטנה יותר של הבעיה
  > זו רקורסיה. ממואיזציה היא דרך להפוך פונקציות רקורסיביות למהירות יותר.
- [ ] הגדלת מגבלת הרקורסיה עם `sys.setrecursionlimit(...)` כדי שתוכל להעמיק יותר
  > זה משנה כמה עמוק הרקורסיה יכולה להגיע, וזה מסוכן. זה לא חוסך שום עבודה.
- [ ] לכתוב תמיד את מקרה הבסיס ראשון כדי שהפונקציה תיעצר
  > זה הרגל טוב כדי להימנע מרקורסיה אינסופית, אבל זו לא ממואיזציה.
- [x] שמירת תוצאות ושימוש חוזר בהן עבור קלטים שחוזרים על עצמם
  > נכון! במקום לחשב את אותה תשובה שוב, הפונקציה פשוט מחפשת אותה.
> חלק מהפונקציות הרקורסיביות, כמו פיבונאצ'י, מחשבות את אותם ערכים הרבה פעמים. ממואיזציה שומרת כל תוצאה בפעם הראשונה שהיא מחושבת, כך שקריאות מאוחרות יותר עם אותו קלט יכולות להחזיר אותה מיד.

## איזו שורה צריכה להחליף את `# missing line` כדי ש-`fib` תזכור את התשובות שלה?
```python
memo = {}

def fib(n):
    if n in memo:
        return memo[n]
    if n <= 1:
        return n
    result = fib(n - 1) + fib(n - 2)
    # missing line
    return result
```
- [x] `memo[n] = result`
  > נכון! זה שומר את התשובה תחת המפתח `n`, כך שהקריאה הבאה עם אותו `n` מוצאת אותה עם `if n in memo`.
- [ ] `memo = {}`
  > זה יוצר מילון ריק חדש בתוך הפונקציה, כך שאף פעם שום דבר לא נשמר ב-`memo` האמיתי.
- [ ] `result = memo[n]`
  > זה קורא מהמילון במקום לכתוב אליו. מכיוון ש-`n` עוד לא נשמר, זה זורק `KeyError`.
- [ ] `memo.append(result)`
  > למילונים אין `.append()`. זו מתודה של רשימה, ורשימה לא הייתה מאפשרת לחפש תשובה לפי `n`.
> כדי לעשות ממואיזציה עם מילון: קודם בודקים אם הקלט כבר קיים כמפתח (`if n in memo`), ואם לא, מחשבים את התשובה ושומרים אותה עם `memo[n] = result` לפני שמחזירים אותה.
