## אילו מהטענות הבאות על Python נכונות?
- [ ] קוד Python רץ בדרך כלל מהר יותר מקוד C או C++.
  > זה בדיוק הפוך. Python היא שפה מפורשת (interpreted), ולכן היא בדרך כלל רצה לאט יותר מ-C או C++. מה שמהיר ב-Python זה *לכתוב* קוד.
- [ ] Python משמשת בעיקר למדעי הנתונים ולא מתאימה לסוגים אחרים של פרויקטים.
  > Python היא שפה כללית (general-purpose). מדעי הנתונים הם רק תחום אחד מתוך הרבה תחומים שבהם משתמשים בה.
- [x] Python משמשת לפיתוח אתרים, ניתוח נתונים, בינה מלאכותית וחישוב מדעי.
  > נכון! Python מאוד גמישה ומופיעה בכל התחומים האלה.
- [x] אפשר להאיץ חלקים איטיים של תוכנית Python בעזרת ספריות מותאמות לביצועים או על ידי כתיבתם בשפה אחרת.
  > נכון! זו הדרך המקובלת לעקוף את מהירות הריצה האיטית יותר של Python.
> ב-Python מהר **לכתוב**, אבל היא יכולה להיות איטית יותר **בריצה** משפות כמו C או C++, כי היא שפה מפורשת. ספריות מותאמות לביצועים עוזרות לצמצם את הפער.

## מה הקוד הזה מדפיס?
```python
a = 5

def foo():
    return a + 10

def bar():
    a = 20

bar()
print(foo())
```
- [ ] 30
  > זה מניח ש-`bar()` שינתה את `a` הגלובלי ל-20. היא לא שינתה: `a = 20` בתוך `bar` יוצר משתנה מקומי חדש.
- [ ] 25
  > בדקו את החשבון: גם אם `a` היה 20, `foo()` הייתה מחזירה 30. ובפועל `a` עדיין 5.
- [ ] שגיאה, כי `foo` לא יכולה להשתמש ב-`a`
  > קריאה של משתנה גלובלי בתוך פונקציה היא דבר תקין לגמרי.
- [x] 15
  > נכון! `bar()` רק יוצרת `a` מקומי, ולכן `a` הגלובלי נשאר 5, ו-`foo()` מחזירה `5 + 10`.
> פונקציה יכולה **לקרוא** משתנה גלובלי בחופשיות. אבל השמה למשתנה בתוך פונקציה יוצרת משתנה **מקומי** חדש, אלא אם מצהירים עליו כ-`global`.

## איזו שורה צריכה להחליף את ההערה כדי שהתוכנית תדפיס 20?
```python
a = 5

def bar():
    # missing line
    a = 20

bar()
print(a)
```
- [x] `global a`
  > נכון! `global a` אומרת ל-Python ש-`a` בתוך `bar` הוא המשתנה הגלובלי, ולכן `a = 20` משנה אותו.
- [ ] `return a`
  > `return` מסיימת את הפונקציה מיד, כך ש-`a = 20` לעולם לא ירוץ. וחוץ מזה, `a` הגלובלי עדיין יהיה 5.
- [ ] `a = a`
  > זה גורם ל-Python להתייחס ל-`a` כמשתנה מקומי, וזה נכשל כי ל-`a` המקומי עדיין אין ערך.
- [ ] כלום, הקוד כבר מדפיס 20
  > בלי `global`, `a = 20` יוצר משתנה מקומי והתוכנית מדפיסה 5.
> כדי **לשנות** משתנה גלובלי מתוך פונקציה, צריך קודם להצהיר עליו עם `global`.

## המשתמש מקליד `7`. מה הקוד הזה מדפיס?
```python
x = input("Enter a number: ")
print(x * 2)
```
- [ ] 14
  > זה היה קורה עם `int(input(...))`. בלי `int`, `x` הוא המחרוזת `"7"`.
- [ ] שגיאה
  > ב-Python מותר להכפיל מחרוזת במספר שלם. זה חוזר על המחרוזת.
- [x] 77
  > נכון! `input` תמיד מחזירה מחרוזת, ו-`"7" * 2` חוזר עליה פעמיים: `"77"`.
- [ ] 7
  > ה-`* 2` כן משנה את התוצאה. מחרוזת כפול 2 היא המחרוזת כתובה פעמיים.
> `input` תמיד מחזירה **מחרוזת**. השתמשו ב-`int(...)` או ב-`float(...)` כדי להפוך אותה למספר.

## מה הקוד הזה מדפיס?
```python
name = "python"
print(f"{name.upper()} has {len(name)} letters")
```
- [ ] `{name.upper()} has {len(name)} letters`
  > ה-`f` לפני המירכאות הופכת את זה ל-f-string, ולכן הביטויים שבתוך `{ }` מחושבים.
- [x] `PYTHON has 6 letters`
  > נכון! `name.upper()` נותנת `"PYTHON"` ו-`len(name)` נותנת 6.
- [ ] `python has 6 letters`
  > `.upper()` הופכת כל אות לאות גדולה.
- [ ] `PYTHON has 5 letters`
  > ספרו שוב: p-y-t-h-o-n זה 6 אותיות.
> ב-f-string, כל מה שבתוך `{ }` מחושב, והערך שלו מוכנס לתוך המחרוזת.

## מה הקוד הזה מדפיס? (כל ערך מודפס בשורה משלו; האפשרויות מציגות אותם בשורה אחת.)
```python
for i in range(8):
    if i == 6:
        break
    if i % 2 == 1:
        continue
    print(i)
```
- [ ] 0 2 4 6
  > כש-`i` שווה 6, `break` יוצאת מהלולאה לפני ש-`print(i)` רץ.
- [ ] 1 3 5
  > `continue` מדלגת על המספרים **האי-זוגיים** (`i % 2 == 1`), כך שהמספרים האי-זוגיים הם דווקא אלה ש*לא* מודפסים.
- [ ] 0 1 2 3 4 5
  > `continue` קופצת לסיבוב הבא של הלולאה, ולכן מדלגים על `print(i)` עבור מספרים אי-זוגיים.
- [x] 0 2 4
  > נכון! על המספרים האי-זוגיים מדלגת `continue`, והלולאה עוצרת לגמרי ב-6 בגלל `break`.
> `continue` מדלגת על שאר הסיבוב הנוכחי ועוברת לסיבוב הבא. `break` יוצאת מהלולאה לגמרי.

## מה הקוד הזה מדפיס?
```python
numbers = [3, 1, 3, 2, 1]
numbers.append(4)
unique = set(numbers)
print(len(numbers), len(unique))
```
- [x] 6 4
  > נכון! אחרי `append(4)` יש ברשימה 6 איברים. הקבוצה (set) שומרת רק את הערכים הייחודיים 1, 2, 3 ו-4.
- [ ] 5 4
  > `append(4)` מוסיפה איבר לסוף הרשימה, אז עכשיו יש בה 6 איברים, ולא 5.
- [ ] 6 6
  > קבוצה לא מאפשרת כפילויות, ולכן ה-3 וה-1 שחוזרים נשמרים רק פעם אחת.
- [ ] 5 3
  > שתי הספירות כוללות את ה-4 ש-`append` הוסיפה: ברשימה יש 6 איברים ובקבוצה יש 4.
> המרה של רשימה לקבוצה היא דרך קלה להסיר כפילויות. הרשימה המקורית לא משתנה.

## מה הקוד הזה מדפיס?
```python
numbers = [2, 4, 6, 8, 10, 12, 14]
print(numbers[1:4])
```
- [ ] [2, 4, 6, 8]
  > החיתוך `[1:4]` מתחיל באינדקס 1, שהוא האיבר השני, 4.
- [ ] [4, 6, 8, 10]
  > החיתוך `[1:4]` עוצר **לפני** אינדקס 4, ולכן 10 לא נכלל.
- [x] [4, 6, 8]
  > נכון! החיתוך `[1:4]` כולל את האיברים באינדקסים 1, 2 ו-3.
- [ ] [2, 4]
  > לאינדקס 4 אין שום קשר לערך 4.
> זכרו שחיתוך רשימות ב-Python כולל את אינדקס ההתחלה ולא כולל את אינדקס הסוף.

## מה הקוד הזה מדפיס?
```python
scores = {"Dana": 80}
scores["Dana"] = 90
scores["Avi"] = 75
print(len(scores), scores["Dana"])
```
- [ ] 2 80
  > `scores["Dana"] = 90` מחליף את הערך הישן, אז הציון של דנה הוא עכשיו 90.
- [ ] 3 90
  > עדכון של `"Dana"` לא מוסיף זוג חדש. כל מפתח מופיע רק פעם אחת, ולכן יש 2 זוגות.
- [x] 2 90
  > נכון! יש שני מפתחות, `"Dana"` ו-`"Avi"`, והערך של דנה עודכן ל-90.
- [ ] 1 90
  > `scores["Avi"] = 75` משתמש במפתח חדש, ולכן הוא מוסיף זוג חדש למילון.
> השמה למפתח קיים **מעדכנת** את הערך שלו. השמה למפתח חדש **מוסיפה** זוג מפתח-ערך חדש.
