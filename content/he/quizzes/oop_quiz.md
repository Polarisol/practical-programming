# בחנו את עצמכם!

ענו על כל השאלות, ואז לחצו על **הגשת התשובות** כדי לראות את הציון ואת התיקונים.

## הסתכלו על השורה `mitzi = Cat("Mitzi", "orange", 2019)`. איזה משפט נכון?
- [ ] `mitzi` היא המחלקה ו-`Cat` הוא האובייקט.
  > זה בדיוק הפוך. השם שאחרי ה-`=` עם הסוגריים (`Cat`) הוא התבנית, ו-`mitzi` הוא מה שמקבלים ממנה.
- [ ] `Cat` הוא בעצמו חתול שאפשר ללטף.
  > מחלקה היא **לא** חתול. היא רק ההוראות להכנת חתולים. אנחנו מלטפים אובייקטים כמו `mitzi`, לא את המחלקה.
- [x] `Cat` הוא התבנית, ו-`mitzi` הוא אובייקט שנוצר ממנה.
  > נכון! המחלקה מתארת מה יש לכל חתול ומה הוא יודע לעשות, ו-`mitzi` הוא חתול אמיתי אחד שנבנה לפי התיאור הזה.
- [ ] כל חתול חדש צריך מחלקה חדשה משלו.
  > מחלקה אחת מספיקה לכמה אובייקטים שרק נרצה. אפשר לכתוב `shadow = Cat(...)`, `snow = Cat(...)` וכן הלאה מאותה מחלקת `Cat`.
> **מחלקה** (class) היא תבנית. **אובייקט** (object) הוא מופע (instance) שנוצר מהתבנית הזו, ומחלקה אחת יכולה ליצור הרבה אובייקטים.

## בעזרת המחלקה `Cat` מהשיעור, מה תדפיס **השורה האחרונה**?
```python
mitzi = Cat("Mitzi", "orange", 2019)
shadow = Cat("Shadow", "black", 2021)

mitzi.pat()
shadow.pat()
mitzi.pat()

print(mitzi.pat_counter, shadow.pat_counter)
```
- [x] `2 1`
  > נכון! את מיצי ליטפו פעמיים ואת שאדו פעם אחת. כל חתול סופר רק את הליטופים שלו.
- [ ] `3 3`
  > זה היה אומר שכל החתולים חולקים מונה אחד. אבל לכל אובייקט יש `pat_counter` **משלו**.
- [ ] `3 1`
  > ספרו שוב: `mitzi.pat()` מופיע רק פעמיים. הליטוף האמצעי הלך לשאדו.
- [ ] `2 2`
  > ליטוף של מיצי לא משנה את שאדו. את שאדו ליטפו רק פעם אחת.
> לכל אובייקט יש **מצב** (state) משלו: ערכים משלו למשתנים שלו. כל החתולים חולקים את אותה מתודה `pat`, אבל המתודה עובדת על הנתונים של החתול שעליו היא נקראה.

## כשאנחנו קוראים ל-`shadow.pat()`, מה המשמעות של `self` בתוך המתודה `pat`?
- [ ] המחלקה `Cat`.
  > `self` הוא לא המחלקה. הוא אובייקט אחד מסוים שנוצר מהמחלקה.
- [x] האובייקט `shadow`.
  > נכון! `self` הוא האובייקט שהמתודה עובדת עליו כרגע, כלומר האובייקט שכתוב לפני הנקודה.
- [ ] החתול הראשון שנוצר אי פעם.
  > `self` משתנה בכל קריאה. ב-`mitzi.pat()` הוא מיצי, וב-`shadow.pat()` הוא שאדו.
- [ ] כל החתולים בבת אחת.
  > קריאה למתודה עובדת על אובייקט **אחד** בלבד. לכן ליטוף של שאדו לא משנה אף חתול אחר.
> בתוך מחלקה, `self` פירושו "האובייקט הזה". לכל מתודה יש `self` כפרמטר הראשון, אבל אנחנו לא מעבירים אותו בעצמנו. Python עושה את זה אוטומטית.

## מתי רצה המתודה `__init__`?
- [ ] רק כשאנחנו כותבים בעצמנו `mitzi.__init__()`.
  > אף פעם לא צריך לקרוא ל-`__init__` בעצמנו כדי ליצור אובייקט. Python קוראת לה בשבילנו.
- [ ] פעם אחת, כש-Python קוראת את השורה `class Cat:`.
  > כתיבת המחלקה רק יוצרת את התבנית. עדיין לא קיים אף חתול, אז אין מה לאתחל.
- [ ] בכל פעם שאנחנו קוראים למתודה כלשהי, למשל `mitzi.pat()`.
  > אם זה היה נכון, `self.pat_counter = 0` היה מאפס את המונה בכל ליטוף, והוא אף פעם לא היה עולה מעל 1.
- [x] אוטומטית, בכל פעם שנוצר אובייקט חדש, למשל `new_cat = Cat("Snow", "white", 2020)`.
  > נכון! `__init__` רצה פעם אחת לכל אובייקט חדש, כדי לקבוע את ערכי ההתחלה שלו.
> `__init__` היא מתודה מיוחדת **שמאתחלת** (initializes) אובייקט חדש. הערכים שאנחנו נותנים בסוגריים, כמו שם וצבע, מועברים אליה.

## הסתכלו על המחלקה הזו. אילו טענות נכונות?
```python
class Car:

    def __init__(self, make, year):
        self.make = make
        self.year = year

    def honk(self):
        print(f"The {self.make} says beep!")


my_car = Car("Toyota", 2015)
```
- [x] `honk` היא מתודה, כי זו פונקציה שכתובה בתוך המחלקה.
  > נכון! פונקציה שכתובה בתוך מחלקה נקראת מתודה (method), וכל אובייקט `Car` יכול להשתמש בה.
- [ ] כדי להשתמש ב-`honk`, חייבים לכתוב `my_car.honk(my_car)`.
  > אנחנו לא מעבירים את `self` בעצמנו. Python מעבירה אותו אוטומטית, אז פשוט כותבים `my_car.honk()`.
- [x] `my_car.year` נותן `2015`.
  > נכון! משתמשים בנקודה כדי לקרוא מידע של אובייקט: `my_car.year` פירושו "השנה של `my_car`".
- [ ] אם היינו קוראים למחלקה `car` במקום `Car`, Python הייתה נותנת שגיאה.
  > Python הייתה מקבלת את `car`. להתחיל שמות של מחלקות באות גדולה זו **מוסכמה** (convention): היא עוזרת לנו להבדיל בין מחלקות למשתנים.
> אנחנו משתמשים **בכתיב הנקודה** (dot notation) כדי להגיע למידע וליכולות של אובייקט: `object.attribute` ו-`object.method()`.

## הנה מחלקה `Animal` ומחלקה `Cat`. מה קורה כשהקוד הזה רץ?
```python
class Animal:

    def __init__(self, name, color, birth_year):
        self.name = name
        self.color = color
        self.birth_year = birth_year
        self.pat_counter = 0

    def pat(self):
        self.pat_counter = self.pat_counter + 1
        print(f"{self.name} is happy... (patted {self.pat_counter} times)")


class Cat(Animal):
    pass


mitzi = Cat("Mitzi", "orange", 2019)
mitzi.pat()
```
- [ ] שגיאה, כי ל-`Cat` אין מתודה `pat`.
  > `Cat` לא כותבת את `pat` בעצמה, אבל היא יורשת אותה. Python לא מוצאת את `pat` ב-`Cat`, אז היא עולה למחלקת האב `Animal` ומוצאת אותה שם.
- [x] מודפס `Mitzi is happy... (patted 1 times)`
  > נכון! `Cat` יורשת גם את `__init__` וגם את `pat` מ-`Animal`, כך שחתול יכול לעשות כל מה שחיה יכולה.
- [ ] לא קורה כלום, כי `pass` אומר שהמחלקה ריקה.
  > `pass` אומר רק "אין שום דבר **נוסף** להוסיף". החתול עדיין מקבל הכול מ-`Animal`.
- [ ] שגיאה, כי ל-`Cat` אין `__init__` והיא לא יכולה לקבל שם.
  > `Cat` משתמשת ב-`__init__` שהיא ירשה מ-`Animal`, שמקבלת שם, צבע ושנת לידה.
> `class Cat(Animal):` פירושו ש-`Cat` יורשת מ-`Animal`. `Animal` היא **מחלקת האב** (superclass), ו-`Cat` היא **מחלקת הבן** (subclass).

## בעזרת המחלקות `Animal`, `Cat` ו-`Dog` מהשיעור, מה קורה **בשורה האחרונה**?
```python
mitzi = Cat("Mitzi", "orange", 2019)
rex = Dog("Rex", "brown", 2018, 4521)

print(mitzi.id_number)
```
- [ ] מודפס `0`
  > רק `pat_counter` מתחיל ב-0. למספר הזיהוי אף פעם לא נקבע ערך ברירת מחדל.
- [ ] מודפס `4521`
  > `4521` הוא מספר הזיהוי של רקס. לכל אובייקט יש מידע משלו, ומיצי היא אובייקט אחר.
- [x] שגיאה, כי לחתולים אין `id_number`.
  > נכון! רק המחלקה `Dog` שומרת מספר זיהוי. `Cat` יורשת רק את מה שיש ל-`Animal`, ול-`Animal` אין מספר זיהוי.
- [ ] לא מודפס כלום, כי מיצי היא חתולה.
  > Python לא מדלגת על זה בשקט. קריאה של משתנה שהאובייקט אף פעם לא שמר גורמת לשגיאה.
> ירושה עוברת רק מהאב לבן. הבן מקבל כל מה שיש לאב, אבל הוא לא מקבל דברים שמחלקה **אחות** (כמו `Dog`) מוסיפה.

## מה הקוד הזה מדפיס?
```python
class Animal:

    def __init__(self, name):
        self.name = name

    def speak(self):
        print(f"{self.name} makes a sound")


class Cat(Animal):

    def speak(self):
        print(f"{self.name} says meow")


class Dog(Animal):
    pass


mitzi = Cat("Mitzi")
rex = Dog("Rex")
mitzi.speak()
rex.speak()
```
- [x] `Mitzi says meow`, ואחר כך `Rex makes a sound`
  > נכון! `Cat` דורסת את `speak` עם גרסה משלה, ואילו `Dog` לא כותבת כלום ושומרת על הגרסה מ-`Animal`.
- [ ] `Mitzi makes a sound`, ואחר כך `Rex makes a sound`
  > כשמחלקת בן כותבת מתודה **באותו שם** כמו של האב, משתמשים בגרסה של הבן. ל-`Cat` יש `speak` משלה.
- [ ] `Mitzi says meow`, ואחר כך `Rex says meow`
  > רק `Cat` שינתה את `speak`. `Dog` יורשת מ-`Animal`, לא מ-`Cat`.
- [ ] `Mitzi makes a sound`, ואחר כך `Mitzi says meow`
  > כל קריאה מריצה `speak` אחת על אובייקט אחד. `rex.speak()` עובדת על רקס, לא על מיצי.
> **דריסה** (overriding) פירושה שמחלקת בן כותבת גרסה משלה למתודה של האב. Python מחפשת קודם במחלקת הבן, ועולה לאב רק אם היא לא מוצאת שם את המתודה.

## המחלקה `Animal` היא זו מהשיעור. במחלקת `Dog` הזו, המתכנת שכח את השורה של `super()`. מה קורה?
```python
class Dog(Animal):

    def __init__(self, name, color, birth_year, id_number):
        self.id_number = id_number


rex = Dog("Rex", "brown", 2018, 4521)
rex.pat()
```
- [ ] מודפס `Rex is happy... (patted 1 times)`, כי `Dog` יורשת מ-`Animal`.
  > `Dog` אכן יורשת מ-`Animal`, אבל ה-`__init__` שלה **מחליפה** את זו של האב. לכן ה-`__init__` של האב אף פעם לא רצה ואף אחד לא מאתחל את מונה הליטופים.
- [ ] Python מריצה אוטומטית את שתי מתודות ה-`__init__`, אז הכול עובד.
  > Python מריצה רק `__init__` אחת: של הבן. כדי להריץ גם את של האב, צריך לקרוא לה עם `super().__init__(...)`.
- [ ] שגיאה כבר בשורה `rex = Dog(...)`.
  > יצירת רקס עובדת: ה-`__init__` של הכלב מקבלת את כל ארבעת הערכים ושומרת את מספר הזיהוי. הבעיה מופיעה אחר כך.
- [x] שגיאה ב-`rex.pat()`, כי לרקס אף פעם לא נוצר `pat_counter`.
  > נכון! השורה `self.pat_counter = 0` נמצאת ב-`__init__` של האב, שאף פעם לא רצה. כש-`pat` מנסה להוסיף 1 ל-`self.pat_counter`, הוא לא קיים.
> כשמחלקת בן דורסת את `__init__`, בדרך כלל היא צריכה לקרוא ל-`super().__init__(...)` כדי שהאב יוכל לאתחל את החלק שלו באובייקט.

## אילו טענות לגבי `super().__init__(name, color, birth_year)` בתוך `Dog` נכונות?
- [ ] היא יוצרת אובייקט `Animal` שני ונפרד.
  > לא נוצר שום אובייקט חדש. ה-`__init__` של האב מאתחלת את **אותו** אובייקט כלב שנמצא בתהליך יצירה.
- [x] היא מריצה את ה-`__init__` של האב, ששומרת את השם, הצבע, שנת הלידה ומונה הליטופים.
  > נכון! `super()` פירושו "מחלקת האב שלי", אז השורה הזו מריצה את ה-`__init__` של `Animal` עבור הכלב הזה.
- [ ] חייבים לכתוב אותה בתוך כל מתודה של המחלקה `Dog`.
  > משתמשים ב-`super()` רק איפה שצריך את הגרסה של האב למתודה. `Dog` לא דרסה את `pat`, אז היא לא צריכה שם `super()`.
- [x] בלעדיה, היינו צריכים להעתיק את שורות האתחול של האב לתוך ה-`__init__` של הכלב.
  > נכון! והעתקת קוד היא בדיוק מה שירושה עוזרת לנו להימנע ממנו: אם האתחול של האב משתנה, היינו צריכים לתקן אותו בשני מקומות.
> `super()` נותנת לנו גישה למחלקת האב. קריאה ל-`super().__init__(...)` בתוך ה-`__init__` של הבן מאפשרת לאב לבצע את האתחול הרגיל שלו, והבן מוסיף רק את מה שחדש.
