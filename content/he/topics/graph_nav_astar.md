# חיפוש A*

## הרעיון

BFS מוצא את המסלול הקצר ביותר, אבל הוא קצת "עיוור". הוא מתפשט לכל הכיוונים באופן שווה, גם לכיוונים שמובילים **הרחק** מהיעד.

כשאתם מחפשים את השירותים בבניין חדש ורואים שלט שמצביע שמאלה, אתם לא מתחילים לחפש בצד הימני של הבניין. אתם הולכים שמאלה, ומנסים דרכים אחרות רק אם הדרך הזו חסומה.

**A\*** (קוראים "איי-סטאר") עובד ככה. הוא עדיין מחפש בזהירות, כמו BFS, אבל הוא משתמש ב**הערכה** של המרחק מכל מקום ליעד, ותמיד מנסה קודם את המקום המבטיח ביותר.

## BFS מול A\* על מפה

הנה רובוט על מפת משבצות. הוא מתחיל ב-`S`, צריך להגיע ל-`G`, ויש קיר באמצע. כל צעד מזיז אותו משבצת אחת למעלה, למטה, שמאלה או ימינה. המשבצות בתכלת הן אלה שכל אלגוריתם נאלץ לבדוק לפני שמצא את היעד:

![אותה מפת משבצות פעמיים. משמאל, BFS סרק 83 משבצות, כמעט את כל המפה. מימין, A* סרק רק 21 משבצות, בעיקר בין S ל-G. שניהם מצאו מסלול של 12 צעדים](content/images/astar_vs_bfs.svg)

שניהם מצאו מסלול קצר ביותר, 12 צעדים. אבל BFS בדק **83** משבצות, כמעט את כל המפה, ואילו A\* בדק רק **21**, בעיקר את המשבצות שמובילות לכיוון היעד. במפה אמיתית עם מיליוני משבצות, ההבדל הזה עצום. זו הסיבה ש-A\* הוא האהוב על מפתחי משחקים ובוני רובוטים.

## שלושת המספרים: g, h ו-f

לכל משבצת שהוא מכיר, A\* שומר שלושה מספרים:

- **g** - כמה צעדים **באמת** לקח להגיע לכאן מההתחלה. את זה אנחנו יודעים בדיוק.
- **h** - **הערכה** (שנקראת **היוריסטיקה**, heuristic) של כמה צעדים נשארו מכאן עד היעד.
- **f = g + h** - האורך המשוער של כל הדרך, אם עוברים דרך המשבצת הזו.

A\* תמיד סורק בשלב הבא את המשבצת עם **ה-f הקטן ביותר**: המשבצת שנמצאת על הדרך שנראית הכי קצרה.

כשלכמה משבצות יש את אותו f מינימלי, A\* לוקח קודם את זו עם **ה-h הקטן ביותר**: זו שלפי ההערכה הכי קרובה ליעד. זה לא משנה את התשובה (A\* עדיין מוצא מסלול קצר ביותר), זה רק עוזר ל-A\* להגיע ליעד מהר יותר במקום לנסות הרבה משבצות טובות באותה מידה זו לצד זו.

הערכה טובה על מפת משבצות היא **מרחק מנהטן** (Manhattan distance): מספר השורות ועוד מספר העמודות בין המשבצת ליעד, כאילו אין קירות. (הוא נקרא על שם הרחובות של מנהטן, שבהם אפשר ללכת רק לאורך רשת של בלוקים.)

```
h = |row - goal_row| + |col - goal_col|
```

לדוגמה, `S` נמצאת בשורה 3, עמודה 2, ו-`G` נמצאת בשורה 3, עמודה 10. ההערכה מ-`S` היא `|3 - 3| + |2 - 10| = 8`. המסלול האמיתי הוא 12 צעדים בגלל הקיר, אבל 8 זו הערכה סבירה לגמרי.

> **כלל הזהב של ההערכה:** מותר לה להיות קטנה מדי, אבל אסור לה **אף פעם להיות גדולה** מהמרחק האמיתי. מרחק מנהטן עומד בכלל הזה, כי קירות יכולים רק להאריך את הדרך, אף פעם לא לקצר אותה. עם הערכה כזו, A\* תמיד מוצא מסלול קצר ביותר. אם ההערכה גדולה מדי, A\* עלול לדלג על המסלול הטוב ביותר ולהחזיר מסלול ארוך יותר.

## דוגמה קטנה ביד

נניח שהרובוט נמצא ב-`S` (g = 0, h = 8, f = 8) ומסתכל על ארבעת השכנים שלו:

| משבצת | g (צעדים עד עכשיו) | h (הערכה עד היעד) | f = g + h |
|--------|------------------|-------------------|-----------|
| מימין ל-`S` | 1 | 7 | **8** |
| מעל `S` | 1 | 9 | 10 |
| מתחת ל-`S` | 1 | 9 | 10 |
| משמאל ל-`S` | 1 | 9 | 10 |

למשבצת שמימין יש את ה-f הקטן ביותר, אז A\* סורק אותה בשלב הבא. הוא ממשיך לזוז ימינה עד שהקיר חוסם אותו. אז למשבצות שמסביב לקיר יש את ה-f הקטן ביותר, אז A\* עוקף את הקיר וממשיך ל-`G`. הוא כמעט אף פעם לא טורח לבדוק את המשבצות שמאחורי `S`, כי ה-f שלהן תמיד גדול יותר.

## בחירת הקטן ביותר: תור עדיפויות

BFS השתמש בתור (הראשון שנכנס הוא הראשון שיוצא), ו-DFS השתמש במחסנית (האחרון שנכנס הוא הראשון שיוצא). A\* צריך **תור עדיפויות** (priority queue): לא משנה מה מכניסים, הפריט עם הערך **הקטן ביותר** תמיד יוצא ראשון. זה כמו חדר מיון בבית חולים, שבו מטפלים קודם בחולה הדחוף ביותר, ולא במי שהגיע ראשון.

ב-Python יש כזה במודול `heapq`:

```python
import heapq

waiting = []
heapq.heappush(waiting, (10, 'above'))
heapq.heappush(waiting, (8, 'right'))
heapq.heappush(waiting, (12, 'far away'))

print(heapq.heappop(waiting))   # (8, 'right') - the smallest number comes out first
```

אנחנו מכניסים `(f, h, square)`, כך שהמשבצת עם ה-f הקטן ביותר יוצאת ראשונה. Python משווה tuples איבר אחרי איבר, אז כששתי משבצות עם אותו f, היא משווה אחר כך את `h`: המשבצת הקרובה יותר ליעד יוצאת ראשונה.

## הקוד

המפה היא רשימה של מחרוזות: `#` הוא קיר, `S` היא נקודת ההתחלה ו-`G` היא היעד. משבצת נשמרת כזוג `(row, col)`.

```python
import heapq

grid = [
    "............",
    "............",
    "......#.....",
    "..S...#...G.",
    "......#.....",
    "......#.....",
    "............",
    "............",
]

def find(symbol):
    for row in range(len(grid)):
        for col in range(len(grid[row])):
            if grid[row][col] == symbol:
                return (row, col)

def neighbours(cell):
    row, col = cell
    result = []
    for d_row, d_col in [(-1, 0), (1, 0), (0, -1), (0, 1)]:   # up, down, left, right
        r, c = row + d_row, col + d_col
        if 0 <= r < len(grid) and 0 <= c < len(grid[0]) and grid[r][c] != '#':
            result.append((r, c))
    return result

def guess(cell, goal):
    # Manhattan distance: rows + columns between the squares, ignoring walls
    return abs(cell[0] - goal[0]) + abs(cell[1] - goal[1])

def a_star(start, goal):
    steps = {start: 0}              # g: the real number of steps from the start
    came_from = {start: None}
    to_visit = [(guess(start, goal), guess(start, goal), start)]  # (f, h, cell): smallest f first, on a tie smallest h
    explored = set()                # squares we already took out of the priority queue

    while to_visit:
        f, h, cell = heapq.heappop(to_visit)
        if cell in explored:        # an older entry for a square we already explored
            continue
        explored.add(cell)
        if cell == goal:
            break
        for nb in neighbours(cell):
            new_steps = steps[cell] + 1
            if nb not in steps or new_steps < steps[nb]:   # a new square, or a shorter way to it
                steps[nb] = new_steps
                came_from[nb] = cell
                heapq.heappush(to_visit, (new_steps + guess(nb, goal), guess(nb, goal), nb))

    if goal not in came_from:
        return None, len(explored)  # the goal cannot be reached

    # walk backwards from the goal to the start, exactly like in BFS
    path = []
    cell = goal
    while cell is not None:
        path.append(cell)
        cell = came_from[cell]
    path.reverse()
    return path, len(explored)

path, explored = a_star(find('S'), find('G'))
print('Squares explored:', explored)   # 21
print('Steps:', len(path) - 1)         # 12
print(path)
```

פלט:

```
Squares explored: 21
Steps: 12
[(3, 2), (3, 3), (3, 4), (3, 5), (2, 5), (1, 5), (1, 6), (1, 7), (1, 8), (1, 9), (1, 10), (2, 10), (3, 10)]
```

המסלול הולך ימינה מ-`S`, עולה ועוקף את הקיר מלמעלה, ויורד אל `G`.

נסו בעצמכם: הזיזו את הקיר, האריכו אותו, או הוסיפו עוד קירות, ותראו איך מספר המשבצות שנסרקו משתנה.

## A\* ובני משפחתו

- אם ההערכה תמיד `0`, A\* מסתכל רק על המרחק האמיתי, והוא מתנהג כמו BFS: מתפשט באופן שווה לכל הכיוונים.
- A\* עובד גם על גרפים **ממושקלים**, כמו מפת העיר במבוא. במקום להוסיף `1` לכל צעד, מוסיפים את המשקל של הכביש (הדקות). עם הערכה `0`, זה **האלגוריתם של דייקסטרה** (Dijkstra) המפורסם, שעליו בנויות אפליקציות הניווט. עם הערכה טובה (למשל, המרחק בקו אווירי עד היעד), הוא הופך ל-A\*.

## מתי להשתמש ב-A\*

- **טוב:** למציאת **המסלול הקצר ביותר ליעד אחד מסוים**, ומהר. זו הבחירה הקלאסית לתכנון מסלולים לרובוטים ולדמויות במשחקי וידאו.
- **טוב:** ככל שההערכה טובה יותר, הוא סורק פחות משבצות.
- **פחות טוב:** צריך הערכה הגיונית. אם אתם לא יודעים איפה היעד (למשל, "מצא את עמדת הטעינה הקרובה ביותר"), אי אפשר לבנות הערכה, ו-BFS או דייקסטרה הם הכלי הנכון.
- **פחות טוב:** זה יותר קוד מ-BFS. במפה קטנה, BFS לרוב מספיק טוב.
