# טיפים למאגר ציבורי טוב

מאגר (repository) ציבורי הוא דלת הכניסה לפרויקט שלכם. מישהו פותח אותו, ותוך דקה הוא צריך לדעת **מה זה**, **איך מריצים את זה**, ושזה **באמת רץ**. הטיפים האלה יביאו אתכם לשם.

## 1. השתמשו ב-uv, ובצעו commit לקבצים שלו

בצעו commit לשלושת הקבצים האלה, כדי שכל אחד יוכל ליצור מחדש בדיוק את הסביבה שלכם:

- `pyproject.toml`: הספריות שהפרויקט צריך
- `uv.lock`: הגרסה המדויקת של כל ספרייה
- `.python-version`: גרסת ה-Python

ואז כדי להריץ את הפרויקט מספיק:

```bash
uv sync
uv run main.py
```

בלי לנחש אילו ספריות להתקין, ובלי "אצלי זה עובד". אם הוספתם כל ספרייה עם `uv add`, הקבצים האלה כבר מעודכנים. בדקו שהם מופיעים ברשימת **Changes**, ובצעו להם commit.

## 2. כתבו README

GitHub מציג את `README.md` בעמוד הראשי של המאגר. שמרו אותו קצר:

- **מה זה**: משפט או שניים.
- **צילום מסך** (או GIF), אם יש חלון או גרף. שימו אותו במאגר, למשל `images/screenshot.png` (ראו בדוגמה למטה).
- **איך מריצים**: הפקודות המדויקות, מה-clone ועד ההרצה.
- **מה עוד צריך**, אם בכלל: מפתח API, קובץ נתונים, התחברות.

````markdown
# Grade Analyzer

Reads a CSV of grades and plots each class's average.

![Screenshot](images/screenshot.png)

## Run it

```bash
git clone https://github.com/<user-name>/grade-analyzer.git
cd grade-analyzer
uv sync
uv run main.py
```
````

> כדי לראות איך ה-README ייראה, פתחו אותו ב-VS Code ולחצו **Ctrl+Shift+V** (תצוגה מקדימה של Markdown).

## 3. השאירו בחוץ זבל וסודות

בדקו את `.gitignore` **לפני ה-commit הראשון**. הוא צריך לכלול לפחות `.venv`, `__pycache__/` ו-`.env`. לפני כל commit, העיפו מבט ברשימת **Changes**: יש שם משהו שלא ציפיתם לו?

- **לעולם אל תבצעו commit לסיסמאות או למפתחות API.** שימו אותם ב-`.env` (שמתעלמים ממנו), ובצעו commit לקובץ `.env.example` עם השמות בלי הערכים, כדי שאחרים יידעו מה למלא.
- **בלי קבצים גדולים.** נתונים גדולים ופלט שנוצר אוטומטית נשארים בחוץ. אם הפרויקט צריך נתונים, הסבירו ב-README מאיפה משיגים אותם.

## 4. ודאו שזה רץ גם במחשב של מישהו אחר

- **בלי נתיבים מהמחשב שלכם.** `C:\Users\Dana\Desktop\data.csv` קיים רק אצלכם. השתמשו בנתיב יחסי לתיקיית הפרויקט, למשל `data/grades.csv`.
- **נקודת התחלה אחת וברורה**, למשל `main.py`, וה-README אומר להריץ אותה.

## 5. הוסיפו רישיון

בלי רישיון (license), אסור לאף אחד להשתמש מחדש בקוד שלכם, גם אם המאגר ציבורי. בעמוד המאגר ב-GitHub לחצו **Add file → Create new file**, קראו לקובץ `LICENSE`, לחצו **Choose a license template**, בחרו **MIT License** ובצעו commit. אחר כך לחצו **Pull** ב-VS Code כדי לקבל את הקובץ החדש.

## 6. מלאו את תיבת ה-"About"

בעמוד המאגר, לחצו על גלגל השיניים ⚙ ליד **About** (למעלה מימין). הוסיפו תיאור של שורה אחת וכמה **topics** (למשל `python`, `pyside6`, `data-analysis`). זה מה שאנשים רואים בתוצאות החיפוש.

## 7. היסטוריה נקייה, שמות ברורים

- **הודעות commit שאומרות מה השתנה** (ראו *מתי לבצע commit*). גם הן ציבוריות.
- **שמות משמעותיים** למאגר, לקבצים ולתיקיות: `grade-analyzer`, ולא `project1-final-v2`.

## המבחן האחרון: שכפלו את המאגר בעצמכם

שכפלו (clone) את המאגר שלכם לתיקייה חדשה וריקה (ראו *שכפול מאגרים*), הריצו `uv sync`, ועקבו אחרי ה-README שלכם. אם זה רץ שם, זה ירוץ גם אצל אחרים. אם משהו חסר, תקנו, בצעו commit ולחצו **Sync Changes**.
