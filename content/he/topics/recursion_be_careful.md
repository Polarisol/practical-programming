# זהירות - גלישת מחסנית (Stack Overflow)

בכל פעם שקוראים לפונקציה, Python שומרת בזיכרון מידע על הקריאה הזו: הפרמטרים שלה, המשתנים המקומיים שלה ולאן לחזור בסיום. אזור הזיכרון הזה נקרא **מחסנית הקריאות** (call stack). המידע נמחק רק כשהקריאה מסתיימת.

ברקורסיה, קריאה לא מסתיימת עד שכל הקריאות שמתחתיה מסתיימות. לכן כל רמה של רקורסיה מוסיפה עוד רשומה למחסנית, וכולן נשארות שם באותו זמן.

מחסנית הקריאות **קטנה מאוד**. יכול להיות שיש למחשב שלכם הרבה ג'יגה-בייטים של זיכרון, אבל המחסנית לא זוכה להשתמש בהם. מערכת ההפעלה נותנת לכל תוכנית אזור קבוע וקטן למחסנית שלה, בדרך כלל רק כמה מגה-בייטים (לרוב בסביבות 8 MB, וב-Windows אפילו רק 1 MB). הוספת זיכרון למחשב לא מגדילה את המחסנית בכלל. כך שפונקציה רקורסיבית יכולה לגמור את המקום במחסנית בזמן שרוב הזיכרון של המחשב יושב ולא עושה כלום.

אז... אם לא נזהר, אנחנו עלולים להיתקל במשהו שנקרא **גלישת מחסנית** (stack overflow). זה קורה כשנגמר המקום במחסנית הקריאות, כי יש יותר מדי קריאות פעילות לפונקציות באותו זמן.

## שוכחים את מקרה הבסיס

אם מקרה הבסיס חסר, או שאף פעם לא מגיעים אליו, הפונקציה קוראת לעצמה לנצח:

```python
def countdown(n):
    print(n)
    countdown(n - 1)   # no base case - it never stops!

countdown(5)
```

אותו דבר קורה כשמקרה הבסיס קיים, אבל הצעד הרקורסיבי מדלג מעליו:

```python
def multiply(a, b):
    if b == 0:
        return 0
    return a + multiply(a, b - 2)   # b goes 3, 1, -1, -3 ... and never hits 0

multiply(4, 3)
```

## עמוק מדי, גם כשהכול נכון

גם פונקציה רקורסיבית נכונה יכולה להיכשל אם הבעיה גדולה מדי. ל-`multiply(4, 5000)` יש מקרה בסיס נכון, אבל היא צריכה 5000 קריאות שמחכות במחסנית בבת אחת.

כדי להגן על המחשב מפני מצב שבו נגמר הזיכרון, Python מגבילה את עומק הרקורסיה (בערך 1000 רמות כברירת מחדל). מעבר לגבול הזה, התוכנית קורסת עם:

```
RecursionError: maximum recursion depth exceeded
```

אפשר לראות את הגבול כך:

```python
import sys
print(sys.getrecursionlimit())  # 1000
```

אפשר להגדיל אותו עם `sys.setrecursionlimit(...)`, אבל זה מסוכן: אם המחסנית באמת נגמרת, Python עצמה יכולה לקרוס בלי שום הודעת שגיאה.

## איך נשארים בטוחים

1. תמיד כתבו את **מקרה הבסיס קודם**, וודאו שכל קריאה מתקדמת **לכיוונו**.
2. השתמשו ברקורסיה כשהעומק נשאר קטן, כמו במגדלי האנוי (העומק = מספר הדיסקיות) או כשמחלקים בעיה לחצי בכל פעם.
3. כשהעומק עלול לגדול יחד עם גודל הקלט (כמו ספירה לאחור ממספר גדול), לולאת `for` או `while` רגילה היא בדרך כלל הבחירה הטובה יותר.
