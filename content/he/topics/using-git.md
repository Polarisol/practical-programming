# עבודה עם Git

Git שומר את ההיסטוריה של הפרויקט שלכם. בכל פעם שאתם מבצעים **commit**, git שומר תמונת מצב (snapshot) של כל הקבצים. אחר כך אפשר לראות מה השתנה, לבטל טעויות או לחזור לכל תמונת מצב קודמת. העמוד הזה עוסק בעבודה עם git לבד, מתוך VS Code. הוא מניח שכבר ביצעתם את כל מה שמופיע ב**התקנה** וב**התחלת פרויקט**.

## לפני שמתחילים: ספרו ל-git מי אתם

Git רושם את השם והאימייל שלכם בכל commit, ומסרב לבצע commit עד שהוא יודע אותם. פתחו את הטרמינל ב-VS Code (**View → Terminal**) וכתבו:

```bash
git config --global user.name "place your name here"
git config --global user.email "place your email here"
```

צריך לעשות את זה רק פעם אחת בכל מחשב. כדי לבדוק מה מוגדר, הריצו `git config --global --list`.

> השתמשו באותו אימייל של חשבון ה-GitHub שלכם, כך שה-commits שלכם יקושרו אליו כשתעלו את הפרויקט בהמשך.

## 1. תצוגת Source Control

כל מה שקשור ל-git ב-VS Code נמצא בתצוגת **Source Control**. פותחים אותה בלחיצה על האייקון בצורת ענף בסרגל השמאלי, או בלחיצה על **Ctrl+Shift+G**.

- **Changes**: הקבצים שהשתנו מאז ה-commit האחרון. האות ליד כל קובץ אומרת מה קרה לו: **U** לא במעקב (untracked, קובץ חדש ש-git עוד לא מכיר), **M** שונה (modified), **D** נמחק (deleted).
- **תיבת ההודעה וכפתור Commit**: כאן כותבים מה עשיתם ושומרים תמונת מצב.
- **Graph**: היסטוריית ה-commits שלכם, החדש ביותר למעלה.

הפינה השמאלית התחתונה של החלון (שורת המצב) מציגה את שם **הענף** (branch) הנוכחי, בדרך כלל `master` או `main`. עוד על ענפים בחלק המתקדם.

> אם תצוגת Source Control מציגה כפתור **Initialize Repository**, התיקייה עוד איננה מאגר (repository) של git. זה קורה אם git לא היה מותקן כשהרצתם `uv init`. לחצו על הכפתור (או הריצו `git init` בטרמינל) כדי לתקן. תצטרכו גם ליצור את הקובץ `.gitignore` בעצמכם (ראו בסעיף הבא).

## 2. הקובץ `.gitignore`

יש קבצים שאסור **לשמור** ב-git: קבצים שנוצרים אוטומטית, שאפשר ליצור מחדש בכל רגע, או שהם גדולים מדי. `uv init` יוצר קובץ `.gitignore` שמפרט אותם. הוא נראה כך:

```gitignore
# Python-generated files
__pycache__/
*.py[oc]
build/
dist/
wheels/
*.egg-info

# Virtual environments
.venv
```

כל שורה היא תבנית. Git מתעלם מכל קובץ ותיקייה שמתאימים לאחת מהן:

- `.venv`: כל דבר בשם `.venv` (כאן, סביבת ה-Python של הפרויקט, ש-uv תמיד יכול ליצור מחדש)
- `__pycache__/`: כל תיקייה בשם `__pycache__` (ה-`/` בסוף אומר "רק תיקיות")
- `*.csv`: כל קובץ שמסתיים ב-`.csv` (`*` פירושו "כל דבר")
- `data/`: כל התיקייה `data`
- `secrets.txt`: קובץ עם השם המדויק הזה
- שורות שמתחילות ב-`#` הן הערות

קבצים שמתעלמים מהם מופיעים באפור בסייר הקבצים של VS Code, ולעולם לא מופיעים ברשימת **Changes**.

אפשר להוסיף שורות משלכם בכל זמן. מועמדים טובים:

- קבצי נתונים גדולים (למשל `*.csv`, `data/`)
- קבצים עם סיסמאות או מפתחות API (למשל `.env`). לעולם אל תעשו להם commit!
- פלט שהקוד שלכם יוצר (למשל `output/`, `*.png` אם אלה גרפים שנוצרים בקוד)

> `.gitignore` משפיע רק על קבצים ש-git עדיין לא עוקב אחריהם. אם כבר עשיתם commit לקובץ ורק אחר כך הוספתם אותו ל-`.gitignore`, git ימשיך לעקוב אחריו. כדי להפסיק, הריצו `git rm --cached <file>` בטרמינל ובצעו commit.

## 3. שמירת השינויים (commit)

commit הוא תמונת מצב של הפרויקט עם הודעה קצרה שמתארת מה השתנה. עשו commit לעתים קרובות: בכל פעם שמשהו עובד, או לפני שאתם מנסים משהו מסוכן.

1. פתחו את תצוגת Source Control (**Ctrl+Shift+G**).
2. הסתכלו ברשימת **Changes**. לחצו על קובץ כדי לראות בדיוק מה השתנה: הגרסה הישנה משמאל, החדשה מימין.
3. כתבו הודעה קצרה בתיבת ההודעה, למשל `Add plot of the results`.
4. לחצו **Commit** (או **Ctrl+Enter** בתוך תיבת ההודעה).

בפעם הראשונה VS Code שואל: *"There are no staged changes to commit. Would you like to stage all your changes and commit them directly?"* בחרו **Always**. מעכשיו, Commit שומר את כל השינויים שלכם.

> **Staging** פירושו לבחור אילו שינויים ייכנסו ל-commit הבא. רחפו עם העכבר מעל קובץ ב-**Changes** ולחצו **+** כדי להכין (stage) רק אותו; קבצים מוכנים עוברים לרשימה **Staged Changes**, ו-Commit שומר רק אותם. כשעובדים לבד, אפשר בדרך כלל לדלג על זה ולעשות commit להכול.

> טיפ: ה-commit הראשון אחרי `uv init` צריך לכלול את כל הקבצים שהוא יצר (`pyproject.toml`, `uv.lock`, `.python-version`, `.gitignore`, `main.py`, `README.md`). כך תמיד אפשר יהיה לשחזר את הפרויקט מההיסטוריה.

אותו דבר בטרמינל:

```bash
git add .                     # stage all changes
git commit -m "Add plot of the results"
```

## 4. תיקון ה-commit האחרון (amend)

שכחתם קובץ, או שיש שגיאת הקלדה בהודעה? במקום לעשות commit נוסף, **תקנו (amend)** את האחרון: השינויים החדשים (וההודעה) מתמזגים לתוכו.

1. בצעו את השינויים החסרים ושמרו אותם.
2. כתבו את ההודעה בתיבת ההודעה. ההודעה החדשה מחליפה את הישנה, אז אם הישנה הייתה בסדר, כתבו אותה שוב.
3. לחצו על **החץ ⌄** הקטן ליד כפתור **Commit** ובחרו **Commit (Amend)**.

אותו דבר בטרמינל:

```bash
git add .
git commit --amend -m "The corrected message"   # new message
git commit --amend --no-edit                    # or: keep the old message
```

> תקנו רק את ה-commit **האחרון**, ורק אם עוד לא העליתם (push) אותו ל-GitHub.

## 5. ביטול שינויים: חזרה ל-commit האחרון

עשיתם בלגן ואתם רוצים את הקבצים בחזרה כפי שהיו ב-commit האחרון?

- **קובץ אחד**: ברשימת **Changes**, רחפו מעל הקובץ ולחצו על החץ **Discard Changes** (↶).
- **הכול**: רחפו מעל הכותרת **Changes** ולחצו **Discard All Changes** (↶).

VS Code יבקש אישור. **אי אפשר לבטל את זה**: השינויים שנזרקו נעלמים לתמיד. זריקת שינויים של קובץ **לא במעקב** (**U**) מוחקת אותו.

אותו דבר בטרמינל:

```bash
git restore main.py     # one file
git restore .           # all tracked files
git clean -fd           # delete all untracked files and folders (careful!)
```

### ביטול ה-commit האחרון עצמו

עשיתם commit מוקדם מדי? לחצו על **⋯** (More Actions) בראש תצוגת Source Control ובחרו **Commit → Undo Last Commit**. ה-commit יוסר מההיסטוריה, אבל הקבצים שלכם יישארו בדיוק כמו שהם, והשינויים שלו יחזרו לרשימת **Staged Changes**. תקנו מה שצריך ועשו commit שוב. (בטרמינל: `git reset --soft HEAD~1`.)

## 6. מסע בזמן: ביקור ב-commit קודם

אפשר להסתכל על הפרויקט בדיוק כפי שהיה בכל commit קודם (למשל כדי לבדוק איך הקוד נראה כשהוא עוד עבד) ואז לחזור.

**לפני שמתחילים, עשו commit לעבודה הנוכחית.** Git לא ייתן לכם לעזוב עם שינויים שלא נשמרו ב-commit ושעלולים להידרס, ובכל מקרה אתם לא רוצים לאבד אותם. בדקו גם את שם הענף בפינה השמאלית התחתונה (למשל `master`): תצטרכו אותו כדי לחזור.

### נוסעים אחורה

1. בתצוגת Source Control, פתחו את החלק **Graph**.
2. לחצו לחיצה ימנית על ה-commit שאתם רוצים לבקר בו ובחרו **Checkout (Detached)**.

כל הקבצים שלכם נראים עכשיו בדיוק כמו שהיו ב-commit הזה. אפשר לפתוח ולהריץ אותם כרגיל. הפינה השמאלית התחתונה מציגה עכשיו את המזהה (ID) של ה-commit (למשל `a1b2c3d`) במקום שם של ענף: המצב הזה נקרא **detached HEAD**. הוא פשוט אומר "אתם מבקרים בעבר, לא נמצאים על ענף".

> בזמן הביקור אפשר להסתכל ולהתנסות, אבל **אל תעשו commit** כאן. commits שנעשים ב-detached HEAD לא שייכים לאף ענף וקל מאוד לאבד אותם. כדי לשמור ניסוי שמתחיל כאן, צרו קודם ענף (ראו בחלק המתקדם).

### חוזרים להווה

1. לחצו על מזהה ה-commit בפינה השמאלית התחתונה.
2. בחרו את הענף שלכם (למשל `master`) מהרשימה.

הקבצים שלכם חזרו ל-commit האחרון.

אותו דבר בטרמינל:

```bash
git log --oneline       # list commits with their IDs
git switch --detach a1b2c3d   # visit commit a1b2c3d
git switch master       # come back (use your branch name)
```

> רוצים לזרוק את כל מה שאחרי commit ישן ובאמת להמשיך משם? בשביל זה יש `git reset --hard <commit-id>`. הפקודה מוחקת את ה-commits החדשים יותר, אז היזהרו. בדרך כלל בטוח יותר להשתמש בענף (בהמשך) או להעתיק את הקוד הישן שאתם צריכים ולעשות לו commit כשינוי חדש.

## 7. מתקדם: ענפים

### מה זה ענף?

עד עכשיו, ה-commits שלכם יצרו קו ישר אחד. **ענף** (branch) הוא קו נפרד של commits. הוא מאפשר לנסות משהו (פיצ'ר חדש, שכתוב גדול) בלי לגעת בקוד שעובד. אם הניסוי מצליח, ממזגים אותו בחזרה; אם לא, פשוט עוברים חזרה ושוכחים ממנו.

שתי מילים שכדאי להכיר:

- **ענף** הוא שם שמצביע על ה-commit האחרון בקו שלו. הענף ברירת המחדל שלכם הוא `master` (או `main`). כל commit חדש על ענף מקדם את השם שלו קדימה.
- **HEAD** פירושו "איפה שאתם נמצאים עכשיו". בדרך כלל הוא מצביע על ענף, כך ש-commits חדשים נכנסים לענף הזה. בסעיף המסע בזמן למעלה, HEAD הצביע ישירות על commit ישן במקום על ענף. בגלל זה הוא נקרא *detached* (מנותק).

```text
            C4 ─ C5          ← experiment
           /
C1 ─ C2 ─ C3 ─ C6            ← master  ← HEAD
```

כאן, `experiment` התפצל מ-`master` אחרי `C3`. אתם על `master` (לשם HEAD מצביע), אז הקבצים שלכם נראים כמו `C6`.

### יצירת ענף ומעבר אליו

1. עשו commit לעבודה הנוכחית.
2. לחצו על שם הענף בפינה השמאלית התחתונה.
3. בחרו **+ Create new branch…**, הקלידו שם (למשל `experiment`) ולחצו **Enter**.

אתם עכשיו על הענף החדש; הפינה השמאלית התחתונה מציגה את שמו. עבדו ועשו commit כרגיל: ה-commits הולכים ל-`experiment`, ו-`master` נשאר כמו שהיה.

> כדי להתחיל ענף מ-commit **ישן** (למשל כדי לשמור ניסוי שהתחלתם בזמן ביקור בעבר), לחצו לחיצה ימנית על ה-commit הזה ב-**Graph** ובחרו **Create Branch…**.

### חזרה לענף הראשי

1. עשו commit לשינויים שלכם (או זרקו אותם).
2. לחצו על שם הענף בפינה השמאלית התחתונה.
3. בחרו `master`.

הקבצים שלכם קופצים בחזרה ל-commit האחרון ב-`master`. אפשר לעבור בין ענפים באותה דרך מתי שרוצים: git מחליף את הקבצים שלכם בכל פעם.

### מיזוג ענף (merge)

הניסוי הצליח ואתם רוצים אותו ב-`master`?

1. עברו ל-`master` (כמו למעלה).
2. לחצו על **⋯** (More Actions) בראש תצוגת Source Control ובחרו **Branch → Merge…**.
3. בחרו `experiment`.

השינויים מ-`experiment` נמצאים עכשיו ב-`master`. אם שני הענפים שינו את אותן שורות, git לא יכול להחליט איזו גרסה לשמור ומדווח על **התנגשות מיזוג** (merge conflict). VS Code מסמן את השורות המתנגשות ומאפשר לבחור *Accept Current Change*, *Accept Incoming Change* או *Accept Both*. שמרו את הקובץ ועשו commit.

### מחיקת ענף

סיימתם עם הענף (מיזגתם אותו, או ויתרתם עליו)? לחצו **⋯ → Branch → Delete Branch…** ובחרו אותו. אי אפשר למחוק את הענף שאתם נמצאים עליו, אז עברו קודם ל-`master`.

### אותו דבר בטרמינל

```bash
git branch                   # list branches (* marks the current one)
git switch -c experiment     # create a branch and move to it
git switch master            # move back to master
git merge experiment         # merge experiment into the current branch
git branch -d experiment     # delete the branch (only if merged)
git branch -D experiment     # delete it even if not merged
```
