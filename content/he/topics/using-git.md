# עבודה עם Git

Git שומר את ההיסטוריה של הפרויקט כרשימה של נקודות שמירה שנקראות **commits**. העמוד הזה מראה את שגרת העבודה היומיומית לבד ב-VS Code, בעזרת הכפתורים של תצוגת **Source Control** (האייקון בצורת ענף בסרגל השמאלי, או **Ctrl+Shift+G**). בלי פקודות בטרמינל.

## לפני שמתחילים

`uv init` כבר הפך את תיקיית הפרויקט למאגר (repository) של git ויצר קובץ `.gitignore`, שמפרט את הקבצים ש-git צריך להתעלם מהם (ראו **כללי .gitignore**).

לפני ה-commit הראשון, git צריך גם לדעת מי אתם. עושים את זה פעם אחת בכל מחשב, בטרמינל של VS Code (**View → Terminal**):

```bash
git config --global user.name "place your name here"
git config --global user.email "place your email here"
```

> השתמשו באותו אימייל של חשבון ה-GitHub שלכם.

## שגרת העבודה

**1. עובדים.** כותבים קוד, לבד או בעזרת סוכן AI.

**2. בודקים ושומרים.** מריצים את הקוד, בודקים שהוא עושה מה שרציתם, ושומרים את כל הקבצים.

**3. עוברים על השינויים.** אחרי קצת עבודה (כמה בדיוק? ראו **מתי לבצע commit**), פותחים את **Source Control**. הרשימה **Changes** מציגה כל קובץ שהשתנה מאז ה-commit האחרון: **M** לקובץ ששונה, **U** לקובץ חדש. לחיצה על קובץ מציגה את הגרסה הישנה והחדשה זו לצד זו. קראו את השינויים, במיוחד אם AI כתב אותם.

![השורה Changes, עם הכפתורים Discard ו-Stage](content/images/git_vscode_changes.svg)

**4. זורקים את מה שלא רוצים.** רחפו עם העכבר מעל קובץ ולחצו על **החץ אחורה** (Discard Changes) כדי להחזיר אותו למצבו ב-commit האחרון. אותו חץ בשורה **Changes** זורק את כל השינויים. זהירות: שינויים שנזרקו נעלמים לתמיד.

**5. מכינים (stage) את השאר.** מרוצים מהשינויים? לחצו על **+** בשורה **Changes**. הקבצים עוברים ל-**Staged Changes**, כלומר הם ייכנסו ל-commit הבא.

![תיבת ההודעה עם כפתור ה-AI, וכפתור Commit](content/images/git_vscode_commit.svg)

**6. כותבים הודעה.** תארו בכמה מילים מה עשיתם, למשל `Add a Save button to the main window`. אפשר ללחוץ על כפתור **הניצוץ** כדי ש-AI יכתוב את ההודעה, אבל קראו אותה לפני ה-commit: לפעמים היא שגויה.

**7. מבצעים commit.** לוחצים על הכפתור הכחול **Commit**. אם שכחתם לכתוב הודעה, VS Code פותח במקום זה קובץ זמני בשם `COMMIT_EDITMSG`. כתבו את ההודעה בשורה הראשונה שלו, שמרו וסגרו אותו, וה-commit יתבצע.

**8. מעלים ל-GitHub.** אחרי commit, אותו כפתור כחול משתנה:

![Publish Branch ו-Sync Changes](content/images/git_vscode_publish.svg)

- **Publish Branch**: הפרויקט עדיין נמצא רק במחשב שלכם. לחיצה אחת יוצרת מאגר ב-GitHub (בחרו פרטי או ציבורי) ומעלה אליו הכול.
- **Sync Changes**: הפרויקט כבר נמצא ב-GitHub. לחיצה מעלה את ה-commits החדשים שלכם (וגם מורידה commits חדשים מ-GitHub, אם יש).

**9. מתחילים כל מפגש עבודה ב-Pull.** אם אתם עובדים על יותר ממחשב אחד, בעותק שב-GitHub עשויים להיות commits שאין לכם עדיין. לפני שמתחילים לעבוד, לחצו על **Pull** בכותרת של החלק **Graph** (חץ שמצביע למטה אל נקודת commit). קודם בצעו commit לשינויים המקומיים, אחרת git לא יבצע pull.

![הכפתור Pull בכותרת של Graph](content/images/git_vscode_pull.svg)

ומשם חוזרים לשלב 1.

## חוזרים אחורה בזמן

לפעמים רוצים לראות את הקוד כמו שהיה קודם: לבדוק איך הוא נראה כשעוד עבד, לגלות מתי באג הופיע לראשונה, או להעתיק פונקציה שמחקתם או שקלקלתם מאז.

**קודם בצעו commit לעבודה הנוכחית.** אחר כך, ב-**Graph**, לחצו לחיצה ימנית על ה-commit שאליו רוצים לחזור ובחרו **Checkout (Detached)**.

![לחיצה ימנית על commit ובחירה ב-Checkout (Detached)](content/images/git_vscode_checkout.svg)

עכשיו כל הקבצים נראים בדיוק כמו שהיו אז, ואפשר לפתוח ולהריץ אותם. הסתכלו כמה שתרצו, אבל **אל תבצעו commit** כאן: commits שנעשים בזמן ביקור בעבר הולכים לאיבוד בקלות.

כדי לחזור להווה, לחצו על **⋯** בראש תצוגת Source Control (מעל הודעת ה-commit), בחרו **Checkout to...** ובחרו **master** (או **main**).

![התפריט ⋯, הפריט Checkout to... והענף master](content/images/git_vscode_back.svg)

הקבצים חוזרים ל-commit האחרון שלכם.
