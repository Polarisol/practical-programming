# BFS - חיפוש לרוחב

## הרעיון

זרקו אבן לבריכה. האדוות מתפשטות בטבעות: קודם זזים המים שממש ליד האבן, אחר כך הטבעת שמסביבם, ואז הטבעת הבאה.

**חיפוש לרוחב** (Breadth-First Search, BFS) סורק גרף בדיוק באותה צורה. הוא מתחיל בצומת אחד ומבקר:

1. קודם, בכל הצמתים שנמצאים במרחק **צעד אחד**.
2. אחר כך, בכל הצמתים שנמצאים במרחק **2 צעדים**.
3. אחר כך 3 צעדים, וכן הלאה, עד שלא נשאר שום דבר חדש.

"Breadth" פירושו "רוחב": BFS הולך **לרוחב** לפני שהוא הולך לעומק.

## דוגמה

אנחנו מתחילים ב-`A` בגרף הדוגמה שלנו. הצבעים מראים כמה צעדים רחוק נמצא כל צומת, והמספרים השחורים הקטנים מראים באיזה סדר BFS מבקר בהם:

![BFS על גרף הדוגמה. A הוא צעד 0, B ו-C הם צעד 1, D, E ו-F הם צעד 2, G הוא צעד 3. המסלול A-B-E-G מודגש](content/images/bfs_layers.svg)

- **צעד 0:** `A` - המקום שבו אנחנו מתחילים.
- **צעד 1:** `B` ו-`C` - השכנים של `A`.
- **צעד 2:** `D`, `E` ו-`F` - השכנים החדשים של `B` ו-`C`.
- **צעד 3:** `G` - הצומת היחיד שעוד לא ביקרנו בו.

מכיוון ש-BFS מגיע לכל צומת דרך **המספר הקטן ביותר האפשרי של צעדים**, בפעם הראשונה שהוא מגיע לצומת, הוא כבר מצא את הדרך הקצרה ביותר אליו. הקו האדום הוא המסלול הקצר ביותר מ-`A` ל-`G`: `A → B → E → G`, 3 צעדים.

## התור: queue

איך BFS זוכר מי הבא בתור? הוא משתמש ב**תור** (queue), בדיוק כמו התור בקפיטריה של בית הספר: מי שהגיע **ראשון** מקבל שירות **ראשון**. צמתים חדשים נכנסים לסוף התור, ואנחנו תמיד לוקחים את הצומת הבא מתחילת התור.

הנה התור בזמן ש-BFS רץ מ-`A`:

| מבקרים ב- | השכנים החדשים שלו נכנסים לתור | התור אחרי זה |
|----------|----------------------------------|----------------------|
| `A` | `B`, `C` | `B C` |
| `B` | `D`, `E` (את `A` כבר ראינו) | `C D E` |
| `C` | `F` | `D E F` |
| `D` | אין חדשים | `E F` |
| `E` | `G` | `F G` |
| `F` | אין חדשים | `G` |
| `G` | אין חדשים | ריק - סיימנו |

שימו לב שכל צומת נכנס לתור לכל היותר פעם אחת. אנחנו מסמנים אותו כ**נראה** (seen) ברגע שהוא נכנס, כך שאף אחד לא מוסיף אותו שוב.

## הקוד

ל-Python יש תור מוכן שנקרא `deque` (מבטאים "דק", כמו deck). `append` מוסיף לסוף, ו-`popleft` לוקח מההתחלה.

```python
from collections import deque

graph = {
    'A': ['B', 'C'],
    'B': ['A', 'D', 'E'],
    'C': ['A', 'F'],
    'D': ['B'],
    'E': ['B', 'F', 'G'],
    'F': ['C', 'E'],
    'G': ['E'],
}

def bfs(graph, start):
    visited = {start}           # nodes we have already seen
    queue = deque([start])      # nodes waiting to be visited, first in - first out
    order = []

    while queue:
        node = queue.popleft()  # take the node that has waited the longest
        order.append(node)
        for neighbour in graph[node]:
            if neighbour not in visited:
                visited.add(neighbour)
                queue.append(neighbour)
    return order

print(bfs(graph, 'A'))   # ['A', 'B', 'C', 'D', 'E', 'F', 'G']
```

> למה לא להשתמש ברשימה רגילה וב-`pop(0)`? זה עובד, אבל הוצאת האיבר הראשון מרשימה ארוכה היא איטית, כי Python צריכה להזיז את כל שאר האיברים מקום אחד קדימה. `deque` מוציא אותו מיד.

## מציאת המסלול הקצר ביותר

לבקר בצמתים זה נחמד, אבל בדרך כלל אנחנו רוצים את **המסלול** עצמו. הטריק: בכל פעם שאנחנו מגיעים לצומת חדש, אנחנו רושמים **מאיזה צומת הגענו**. כשאנחנו מגיעים ליעד, אנחנו עוקבים אחרי הרשימות האלה אחורה, מהיעד אל ההתחלה, כמו ללכת בעקבות פירורי לחם.

```python
def shortest_path(graph, start, goal):
    came_from = {start: None}   # for every node we reach: the node we came from
    queue = deque([start])

    while queue:
        node = queue.popleft()
        if node == goal:
            break
        for neighbour in graph[node]:
            if neighbour not in came_from:
                came_from[neighbour] = node
                queue.append(neighbour)

    if goal not in came_from:
        return None             # there is no way to reach the goal

    # walk backwards from the goal to the start
    path = []
    node = goal
    while node is not None:
        path.append(node)
        node = came_from[node]
    path.reverse()
    return path

print(shortest_path(graph, 'A', 'G'))   # ['A', 'B', 'E', 'G']
print(shortest_path(graph, 'D', 'F'))   # ['D', 'B', 'E', 'F']
```

כאן `came_from` עושה שתי עבודות: הוא זוכר את הדרך חזרה, והוא גם האוסף שלנו של "כבר ראינו".

## מתי להשתמש ב-BFS

- **טוב:** BFS תמיד מוצא את המסלול עם **הכי מעט צעדים**. במפת רשת (grid) שבה כל תזוזה עולה אותו דבר, זה המסלול הקצר ביותר עבור רובוט.
- **טוב:** הוא פשוט, והוא אף פעם לא הולך לאיבוד בדרך ארוכה ושגויה.
- **פחות טוב:** הוא מחפש **לכל הכיוונים באותה מידה**, גם בכיוון שמתרחק מהיעד. במפה גדולה הוא בודק מספר עצום של משבצות (תראו את זה בפריט של A\*).
- **פחות טוב:** הוא סופר צעדים, לא מרחקים. אם לדרכים יש אורכים שונים (משקלים), המסלול עם פחות דרכים הוא לא תמיד המהיר ביותר.
