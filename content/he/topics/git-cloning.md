# שכפול מאגרים (Clone)

מאגר (repository) ב-GitHub הוא עותק של פרויקט, כולל כל ההיסטוריה שלו. **שכפול** (clone) מוריד אותו למחשב שלכם: את כל הקבצים, ואת היסטוריית ה-git, כשהם כבר מחוברים ל-GitHub. משתמשים בזה כדי להתחיל לעבוד על פרויקט מ-GitHub (שלכם, של הקורס או של חבר), או כדי להמשיך את הפרויקט שלכם במחשב אחר.

## 1. מצאו את הכתובת של המאגר

בעמוד של המאגר ב-GitHub לחצו על הכפתור הירוק **Code** והעתיקו את הכתובת שמתחת ל-**HTTPS**. היא נראית כך:

```text
https://github.com/<user-name>/<repository-name>.git
```

> אם אתם יודעים את שם המשתמש ואת שם המאגר, אפשר פשוט לכתוב את הכתובת בעצמכם. ה-`.git` בסוף לא חובה.

## 2. שכפלו לתוך תיקייה ב-VS Code

1. צרו תיקייה חדשה **וריקה** לפרויקט, למשל `C:\Projects\my-project`.
2. ב-VS Code בחרו **File → Open Folder…** ופתחו אותה.
3. פתחו את הטרמינל (**View → Terminal**) וכתבו `git clone`, את הכתובת, ואחריה נקודה:

```bash
git clone https://github.com/<user-name>/<repository-name>.git .
```

**הנקודה** בסוף פירושה "לתוך התיקייה הנוכחית". קובצי הפרויקט מופיעים ישירות בתיקייה שפתחתם, ו-VS Code כבר מציג אותם בסייר הקבצים ובתצוגת Source Control.

> בלי הנקודה, git יוצר **תיקייה חדשה** בשם המאגר בתוך התיקייה הנוכחית, ותצטרכו לפתוח את התיקייה הזו ב-VS Code. עם הנקודה התיקייה חייבת להיות ריקה, אחרת git מסרב (*"destination path '.' already exists and is not an empty directory"*).

> מאגר **פרטי** (private) יבקש מכם להתחבר ל-GitHub בפעם הראשונה. בחרו באפשרות של הדפדפן ואשרו. מאגר ציבורי (public) כל אחד יכול לשכפל.

אפשר לשכפל גם בלי הטרמינל: בתצוגת Source Control (**Ctrl+Shift+G**) של חלון ריק לחצו **Clone Repository**, הדביקו את הכתובת ובחרו תיקייה.

## 3. `uv sync`: יוצרים מחדש את סביבת הפייתון

התיקייה `.venv` (סביבת הפייתון של הפרויקט עם כל הספריות) מופיעה ב-`.gitignore`, ולכן היא **לא** נמצאת ב-GitHub ולא בעותק ששכפלתם. יוצרים אותה מחדש בפקודה אחת:

```bash
uv sync
```

uv קורא את `pyproject.toml` ואת `uv.lock`, מתקין את גרסת הפייתון הנכונה, יוצר את `.venv` ומתקין בדיוק אותן ספריות, בדיוק באותן גרסאות. אחרי זה אפשר להריץ את הקוד כרגיל. אם VS Code שואל באיזה פייתון להשתמש, בחרו את זה שבתוך `.venv`.

> הריצו `uv sync` שוב בכל פעם שאתם מושכים (pull) שינויים שהוסיפו או הסירו ספריות (כלומר שינו את `pyproject.toml` או את `uv.lock`). לא בטוחים? פשוט הריצו: אם שום דבר לא השתנה, הוא לא עושה כלום.

## 4. מתחילים כל עבודה ב-Pull

מאגר יכול להשתנות ב-GitHub כשאתם לא שם: דחפתם (push) ממחשב אחר, או שמישהו אחר דחף. העותק שלכם לא יודע על זה עד שאתם **מושכים** (pull).

**בכל פעם שאתם מתיישבים מול מחשב, או פותחים מאגר שלא השתמשתם בו זמן מה, קודם כל לחצו Pull.** בתצוגת Source Control, ‏Pull הוא הכפתור עם **חץ שמצביע למטה אל קו** (↧). Pull מוריד את ה-commits החדשים מ-GitHub ומעדכן את הקבצים שלכם לפי בסיס הקוד שב-GitHub.

עבודה על קבצים ישנים ורק אחר כך pull היא הדרך לקבל **התנגשויות מיזוג** (merge conflicts): אותן שורות שונו בשני מקומות. pull בהתחלה מונע את רובן.

> Pull מסרב אם יש לכם שינויים שלא נשמרו ב-commit בקבצים שהוא צריך לעדכן. בצעו להם commit (או בטלו אותם) ומשכו שוב.

## 5. תוך כדי עבודה: Commit ואז Sync Changes

ה-commits שלכם נשמרים רק במחשב שלכם עד שאתם שולחים אותם ל-GitHub. תוך כדי עבודה משתמשים פעמיים **באותו כפתור כחול** בתצוגת Source Control:

1. **לחיצה ראשונה: Commit.** כתבו הודעה ולחצו **Commit**. זה שומר תמונת מצב במחשב שלכם.
2. **לחיצה שנייה: Sync Changes.** אחרי ה-commit, אותו כפתור הופך ל-**Sync Changes ↑1** (המספר הוא כמה commits מחכים). לחצו עליו כדי לעדכן את הענן: הוא מושך commits חדשים מ-GitHub ואז דוחף את שלכם.

עשו את זה בכל פעם שאתם מסיימים חלק בעבודה, ותמיד לפני שאתם עוזבים את המחשב, כך של-GitHub ולמחשבים האחרים שלכם יהיה הקוד העדכני. (החצים המסתובבים בפינה השמאלית התחתונה של החלון, וכפתור Push עם החץ שמצביע **למעלה**, ↥, עושים אותו הדבר.)


## אותו הדבר בטרמינל

```bash
git clone https://github.com/<user-name>/<repository-name>.git .   # clone into this folder
uv sync          # recreate .venv and install the libraries
git pull         # get the latest commits from GitHub
git push         # upload your commits to GitHub
git status       # where am I? anything to commit, pull or push?
```
