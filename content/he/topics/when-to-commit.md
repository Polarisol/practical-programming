# מתי לבצע commit

commit הוא נקודת שמירה שתמיד אפשר לחזור אליה. כלל האצבע: **בצעו commit בכל פעם שהייתם מצטערים לאבד את מה שעשיתם עכשיו.**

## בצעו commit כש

- **משהו עובד.** הפונקציה מחזירה את התשובה הנכונה, החלון נפתח, הגרף נראה טוב. בצעו commit לפני שאתם נוגעים בזה שוב.
- **לפני משהו מסוכן.** עומדים לארגן מחדש את הקוד, למחוק קוד, או לתת ל-AI לעשות שינוי גדול? בצעו commit קודם, כדי שתוכלו לחזור בלחיצה אחת.
- **אחרי שה-AI שינה את הקוד, ובדקתם אותו.** עברו על השינויים ברשימת **Changes**, בטלו את מה שלא רציתם, ובצעו commit לשאר.
- **סיימתם משימה קטנה אחת.** "הוספת כפתור שמירה", "תיקון קריסה כשהקלט ריק". רעיון אחד בכל commit.
- **לפני שאתם עוזבים את המחשב.** בצעו commit, ואחר כך **Sync Changes** כדי שהעבודה תהיה גם ב-GitHub.

## אל תבצעו commit ל

- **קוד שלא רץ**, אם אפשר להימנע מזה. כל commit צריך להיות נקודה שתרצו לחזור אליה. (סוף היום הוא החריג: בצעו commit בכל זאת, וכתבו את זה בהודעה, למשל `WIP: plot not finished`.)
- **עבודה של יום שלם ב-commit אחד.** אם משהו נשבר, אי אפשר לדעת איזה שינוי גרם לזה, וחזרה אחורה מוחקת הכול.
- **קבצים שמקומם ב-`.gitignore`**: `.venv`, נתונים גדולים, פלט שנוצר אוטומטית, ולעולם לא סיסמאות או מפתחות API.

## כל כמה זמן?

ברוב הקורס: **כל 15 עד 30 דקות של עבודה**, או בכל פעם שסיימתם צעד קטן. commit קטן לא עולה כלום, והרבה נקודות שמירה קטנות שימושיות הרבה יותר מכמה גדולות.

## שכחתם לבצע commit הרבה זמן?

זה קורה. שום דבר לא אבד: השינויים עדיין נמצאים בקבצים, Git פשוט עוד לא שמר אותם. אל תיבהלו, ואל תחמירו את המצב בכך שתשנו עוד קוד קודם.

1. **בצעו commit עכשיו, לפני כל דבר אחר.** ככל שמחכים יותר, השינוי נעשה גדול ומסובך יותר.
2. **עברו על רשימת Changes.** לחצו על כל קובץ כדי לראות מה השתנה. זה גם מזכיר לכם מה עשיתם.
3. **אם העבודה מתחלקת לכמה רעיונות נפרדים, בצעו כמה commits.** העבירו את העכבר מעל קובץ ולחצו על **+** (Stage Changes) כדי להכין רק אותו, כתבו הודעה רק לחלק הזה, ובצעו commit. חזרו על זה לקבוצת הקבצים הבאה. בתצוגת ההשוואה (diff) אפשר אפילו לסמן כמה שורות, ללחוץ על הכפתור הימני ולבחור **Stage Selected Ranges**.
4. **אם הכול שינוי אחד מסובך, commit אחד זה בסדר.** כתבו הודעה שמתארת את כל השינוי, למשל `Add the results window and export to CSV`. commit גדול אחד וכן עדיף בהרבה מאף commit.
5. **Sync Changes**, כדי שהעבודה תהיה גם ב-GitHub.

ואז קבעו לעצמכם הרגל: commit בכל פעם שסיימתם צעד קטן.

## כתבו הודעה מועילה

ההודעה צריכה לומר **מה ה-commit עושה**, בקצרה ובאופן ספציפי:

| לא טוב | טוב |
|-----|------|
| `changes` | `Add a Save button to the main window` |
| `fix` | `Fix crash when the input file is empty` |
| `asdf` | `Plot grades by class as a bar chart` |

> לפני כל commit, העיפו מבט ברשימת **Changes**. אם יש שם קובץ שאתם לא מכירים, בררו למה לפני שאתם מבצעים לו commit.
